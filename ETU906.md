# ETU906Axx-E fork

Based on [likeablob/libfprint-fmv-etu906axx-e](https://github.com/likeablob/libfprint-fmv-etu906axx-e)
commit `e105528828a04dffde789cda48742c204183386d`. This remains a C/libfprint
driver using GLib, GUsb and OpenSSL. Fingerprint matching runs on the sensor;
fprintd retains its existing D-Bus authorization and fingerprint storage.
The upstream license and authorship notices are retained.

## Status

Version 0.1.1 adds certificate failure diagnostics to the normal fprintd error:
chain depth (0 is the model certificate), validity dates in GMT, SHA-256
fingerprint, subject and issuer. Names are escaped; output is limited to 4096
bytes of certificate details. Only public metadata is reported. Verification
policy is unchanged, and expired certificates still prevent opening the device.

Hardware report (2026-09-19, LIFEBOOK, USB 1c7a:05b1, v0.1.0): fprintd discovers
the sensor, but claiming it for enrollment fails with "certificate has expired".
The host clock is synchronized. The actual certificate dates and fingerprint
have not yet been captured; v0.1.1 provides that diagnostic information.

Development only. Do not use this build for host authentication until the
cryptographic, cancellation and suspend reviews and hardware checks below pass.
No hardware enrollment, login or unlock success is claimed by this fork.

The verifier checks the certificate chain and validity period, both attestation
signatures, and the connection/identify MAC. Invalid or expired certificates are
errors; there is no expiry override. Enroll/verify/identify establishes a fresh SDCP connection before each operation,
including after idle suspend. Verify/identify also sends a fresh host nonce.
This adds one handshake per operation and avoids retaining stale authentication
keys across sleep without changing the shared device suspend API.
Firmware that requires a zero nonce must be investigated, not silently accepted.
The repository's existing Egis recording carries a `Secure BIO Sensor` model
certificate valid from 2022-01-04 through 2023-04-04. It is not evidence of
current successful authentication: accepting that expired certificate would
violate the verification policy. This does not establish the certificate dates
of the LIFEBOOK sensor that has not yet been queried.

## Packaging contract

`libfprint-etu906` targets Ubuntu 26.04 amd64 and Fedora 44 x86_64. 32-bit x86,
ARM and concurrent use with sensors outside this private build are not supported.
The private runtime library lives in the distribution library directory's
`libfprint-etu906` subdirectory. A vendor `fprintd.service.d` drop-in selects it
with `LD_LIBRARY_PATH`. The standard libfprint files and global linker configuration
remain untouched. Installing or removing the package reloads systemd and restarts
an already-running fprintd, so any current fingerprint operation is interrupted.
Removal selects the distribution library again; it does not erase fingerprint
data or change PAM/password authentication.

Package installation is intentionally separate from enabling desktop/PAM
fingerprint authentication. Keep an authenticated password session available
while validating a driver, and confirm password fallback before enabling login.

## Security review follow-up

The repository-wide review fixes bound USB lengths and fixed-array copies,
propagate malformed input through error completion, reject invalid saved print
IDs, and handle degenerate image arithmetic. Sanitizer CI now compiles the
reviewed legacy drivers as well as Egis; runtime packages still contain only
`egismoc`. The Egis command lengths use the existing big-endian byte writer;
redundant array-length variables and an unreachable enrollment state were removed.

Capture budgets are host-side limits, independent of device termination signals:
AES2501 uses its existing 150-frame limit; AESX660, Egis0570 and VFS301 allow
approximately 1 MiB of image storage per swipe, and VFS0050 allows 8 MiB of raw
rows (which include repeats). Exceeding a budget reports a protocol error instead
of submitting a partial scan. These limits pass the existing capture replays;
unusually long real-device swipes have not been validated.

The review follow-up rebuilt both package formats, with eight package tests
passing on each OS. The clean install/remove row above records the earlier
packaging validation; the same smoke checks remain required in CI. No new host
package, PAM setting, storage format or production dependency was introduced.
The existing pixman dependency is now enabled when Egis0570 is selected alone.

## Hardware acceptance

Use the distribution's fprintd clients in a host terminal after all blocking
review findings have been resolved. Record the package commit/version, OS,
kernel, firmware/certificate details and each result. Never publish biometric
capture data, private keys or session secrets in a log.

1. Confirm the USB ID is `1c7a:05b1`, and that fprintd loads the private library.
2. Enroll a selected finger, verify it repeatedly, and reject a different,
   unregistered finger. Delete only the chosen enrolled print and verify its
   removal. Do not clear existing sensor storage automatically.
3. Reopen, reboot, and suspend/resume both while idle and while waiting for a
   finger. Ensure errors/cancellation complete once and a fresh connection is
   established after resume.
4. Check desktop login and lock/unlock, including password fallback.
5. Remove the package; confirm the standard library is used and password
   authentication and stored fingerprint data remain available.
6. Repeat enrollment/verification in Fedora 44 with the same USB sensor passed
   through and SELinux enforcing. Until done, Fedora hardware support is unverified.

Tags `vX.Y.Z` are intended to publish the two OS-specific packages, the exact
corresponding source archive and SHA-256 checksums only after both OS checks
succeed. Versions `v0.*` are prereleases. Each release must retain an explicit
hardware verification record; a successful CI run alone is insufficient.
